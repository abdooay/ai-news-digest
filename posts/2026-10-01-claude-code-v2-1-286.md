## What changed

Claude Code (Anthropic's command-line coding tool) shipped version 2.1.286. Notable additions:

- When several permission requests stack up (for example, multiple tool calls each needing approval), the prompt now shows a count like "2 of 5" so you know how many are left.
- Mouse support was added for the "N more" rows that appear at the top or bottom of long lists in fullscreen mode — clicking one now jumps to that end of the list.

Selected bug fixes:
- Multiple Claude Code processes or IDE extensions no longer each pop open a separate login browser window when cloud credentials (Google Cloud or AWS authentication) expire at the same time.
- `claude --resume` and `--continue` could previously lose an entire turn of conversation after a batch of parallel tool calls, if the earlier session had crashed or been killed. That's fixed.
- A tool or hook returning a non-text value (an object, number, or boolean) instead of text caused a 400 error from the API; this is now handled correctly, including in resumed sessions.
- Cloud sessions with very large conversation histories could get stuck and never wake up, because their container shut down while the transcript was still loading. Fixed.
- The usage/spend meter was pricing some prompt-cache writes at the wrong (cheaper) rate and undercounting input tokens on streamed turns that use a server-side tool like web search.
- On macOS, Claude Code could keep showing "Not logged in" after `/login` succeeded in another window, if a leftover credentials file remained. Fixed.
- If the Anthropic API refuses to serve the model your default setting or a model alias points to, Claude Code now automatically retries once on the previous model of the same tier instead of just failing.
- Remote Control sessions used to stay connected even after an organization turned the Remote Control feature off; they now disconnect and show a notice.
- `claude auth status` was misreporting a Console sign-in's API key as a `claude.ai` login; it now correctly reports it as an API-key session.

## Why it matters

Most of this release is about reliability rather than new capability: fewer confusing duplicate login prompts, fewer lost conversation turns after a crash, and more accurate spend tracking. The model-fallback retry fix is useful if you rely on model aliases (like "the latest Sonnet") — a single refusal from the API will no longer stop your turn outright. The permission-prompt counter is a small but welcome usability fix for anyone running Claude Code in a mode that asks before each tool use.

## How to use it

- Update Claude Code to v2.1.286 or later (it self-updates by default, or use your package manager's update command).
- No configuration changes are needed to get the fixes above; they apply automatically once updated.
