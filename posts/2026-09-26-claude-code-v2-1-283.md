## What changed

Claude Code (Anthropic's command-line coding agent) shipped v2.1.283. Notable changes:

- **`/doctor prompt-audit`** (also available as `/checkup prompt-audit`): scans your CLAUDE.md files, skills, agents, and custom commands for prompting patterns written for older Claude models, so you can spot and update stale instructions.
- **New admin controls**: organizations can now set a `deniedModels` list to block specific models even if a broader `availableModels` list would otherwise allow them, and an `availableModelsMatch: "exact"` setting so a listed model only allows that exact version — meaning new model releases stay blocked until an admin explicitly adds them.
- **Gateway hint header**: a new `x-claude-code-prompt-id` header (opt-in via `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`) lets an LLM gateway (a proxy server between Claude Code and Anthropic's API) group all the requests that come from a single user prompt.
- **MCP (Model Context Protocol) fixes**: progress updates from a long-running MCP tool call are no longer lost when the call moves to the background; a stdio MCP server that was still starting up no longer gets left running after the session ends; a brief 404 error from a remote MCP server (for example, during a proxy redeploy) no longer permanently breaks that server for the rest of the session.
- **Plugin fixes**: several bugs in `claude plugin validate`, `claude plugin details`, `claude plugin uninstall`, and marketplace removal that gave misleading or wrong results (like showing 0 MCP servers for a plugin that has some, or uninstalling the wrong plugin when two ids differ only by case) are fixed.
- **Windows fix**: the PowerShell tool no longer lets commands like `cmd /c rd`, `rmdir`, `del`, or `erase` delete drive roots or the home folder — protections that already existed for the equivalent `Remove-Item` command.
- **Vim mode**: several fixes to how `.` (repeat), `J` (join lines), and cursor placement behave, to better match real Vim.
- Smaller improvements: `/tasks`, `/mcp`, and various list-based menus now support mouse wheel scrolling and paging keys; MCP tool outputs can now be included in OpenTelemetry logs; the compaction (conversation-summarizing) progress spinner now shows a running timer and streamed token count instead of a percentage bar.

## Why it matters

The prompt-audit check helps teams keep instruction files up to date as Claude models change — old workarounds written for a previous model can quietly waste tokens or produce worse results. The new `deniedModels` and exact-match settings give organizations tighter control over which models employees can use, which matters for cost control and compliance. The MCP and plugin fixes remove several ways a session could silently lose functionality (a stuck server, missing progress updates, or a wrongly-uninstalled plugin) without a clear error.

## How to use it

- Update with `claude update`, or through the package manager you installed Claude Code with, to reach v2.1.283.
- Run `/doctor prompt-audit` (or `/checkup prompt-audit`) to check your project's CLAUDE.md, skills, agents, and commands for outdated prompting patterns.
- Organizations can add `deniedModels` and `availableModelsMatch` to their managed settings to control which models are usable.
- Set `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` to send the new `x-claude-code-prompt-id` header if your LLM gateway can use it for request grouping.
