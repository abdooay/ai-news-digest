## What changed

Claude Code is Anthropic's command-line coding agent. Version 2.1.317 adds two notable safety-and-control features, plus many bug fixes:

- **A check before your email address leaves your machine**: Claude Code now asks for confirmation before a web request or shell command sends your account's email address over the network. This guards against a site or script silently harvesting your email.
- **Hooks can now block on failure**: hooks are custom scripts that run automatically around Claude Code's actions (for example, before or after a tool call). Agent SDK (the toolkit used to build custom Claude-based tools) hook callbacks can now set `onFailure: "block"`, so if the callback itself fails, the action it was guarding is blocked instead of being allowed to run anyway.
- **A warning when a scheduled cloud task adds unexpected connectors**: `/schedule` (the command for setting up a task that runs later in the cloud) now warns you if a new scheduled task would get access to connectors (integrations like Slack or GitHub) that you didn't explicitly ask for, and tells you how to remove them.
- **New cost-reporting tools for organizations**: the Claude apps gateway (a proxy some companies run in front of Claude) gained an admin API endpoint, `GET /v1/organizations/analytics/cost`, for pulling past spending over a date range — in total, per developer, per day, or per identity-provider group.

The release also fixes many smaller bugs, including: MCP servers (Model Context Protocol servers, which extend Claude with extra tools) disconnecting after the first turn in some desktop sessions; `claude auth status` sometimes signing you out if it exited before a slow token refresh finished saving; a project's effort-level setting being ignored in some pre-started sessions; and a region or network block being wrongly shown as a sign-in failure.

## Why it matters

The email-address check closes a quiet privacy gap: without it, a tool call or script could send your email to a third party without you noticing. The stricter hook-failure behavior matters for anyone relying on hooks for safety checks (like blocking risky commands) — before this change, a broken hook could silently let an action through instead of stopping it, which defeats the purpose of having the hook at all.

The scheduled-task connector warning and the new cost API are mainly useful for teams: the former prevents a scheduled task from silently gaining more access than intended, and the latter gives admins a way to see spending broken down by developer or team without building their own tooling.

## How to use it

- Update Claude Code with `claude update`, or through your package manager, to get v2.1.317.
- The email-address check and the connector warning on `/schedule` apply automatically — no setup needed.
- To make an Agent SDK hook callback block on its own failure, set `onFailure: "block"` on that hook.
- To pull cost data, an organization admin can call `GET /v1/organizations/analytics/cost` on the Claude apps gateway's admin API.
