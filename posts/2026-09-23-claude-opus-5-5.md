## What changed

On September 22, 2026, Anthropic released Claude Opus 5.5, a new version of its Opus model line. Anthropic says it "performs at the level of Claude Fable 5.1 on most work" — Fable 5.1 is Anthropic's most capable model — while costing 40% less to run than the previous Opus 5, and generating output more than 30% faster.

Opus 5.5 has a 1 million token context window by default (a "token" is roughly a word-piece; 1 million tokens is around 750,000 words of text the model can consider at once) and a 128,000 token maximum output length. It always thinks before answering — there's no way to fully turn off its internal reasoning step anymore (see "How to use it" below).

On benchmarks (standardized tests used to compare model quality), Anthropic reports:
- 66.4% on Terminal-Bench 4.0 (a test of using a command-line terminal to complete tasks)
- 54.4% on FrontierCode (a coding benchmark)
- 1846 Elo on GDPval-AA v2.1 (a knowledge-work comparison score)
- 81.8% on OSWorld 2.0 (a test of operating a computer's graphical interface)

Anthropic also cites two examples: one early tester finished a 680,000-line code migration in under a day, work they say would normally take an engineering team weeks. In a web-optimization task, Opus 5.5 succeeded 39 out of 40 times, while Opus 5 made smaller improvements that sometimes also changed the app's behavior in unwanted ways.

## Why it matters

For anyone already paying for Opus-tier models, this is a straightforward upgrade: similar or better quality, lower cost, and faster responses. The price cut is real money for high-volume users — input tokens drop from $5 to $4 per million, output from $25 to $20 per million, and cached-content reads from $0.50 to $0.20 per million (a "cache read" is a discounted rate for reusing context the model has already processed, like a long system prompt).

The change that will affect existing code the most is that "thinking" (the model's step-by-step reasoning before it answers) can no longer be switched off on Opus 5.5. Code that explicitly disables thinking will now get an error instead of a plain, non-reasoning answer.

## How to use it

- The model ID is `claude-opus-5-5`. It's available on the Claude API, Amazon Bedrock, Google Cloud, and Microsoft Azure/Foundry.
- Claude Code (Anthropic's command-line coding tool) made Opus 5.5 its default Opus model starting in v2.1.280 — see the companion post on that release.
- Don't send `thinking: {"type": "disabled"}` — it now returns a 400 error. Leave out the `thinking` field and use the `effort` parameter instead to control how much the model reasons.
- The `tool_choice` settings `any` (force some tool call) and `tool` (force a specific tool) also now return a 400 error on Opus 5.5. Use `auto` and rely on strict tool-use instead.
- If you use the computer-use tool (letting Claude control a computer screen) on the Claude API or Google Cloud, switch to the `computer_toolset_20260801` toolset — the older `computer_20251124` tool now returns a 400 error there. It still works on Amazon Bedrock.
- A "Fast Mode" research preview is available for Opus 5.5 on the Claude API, for lower-latency responses.
- A new beta lets you add or change tool definitions in the middle of a conversation, via a system message, without breaking prompt caching. It needs the `inline-tools-2026-09-15` beta header.
- Anthropic says Opus 5.5 includes added safeguards for cybersecurity and biology-related requests. Organizations that need full access to biology capabilities for legitimate research can apply through Anthropic's Life Sciences Verification Program.
