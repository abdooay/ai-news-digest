## What changed

Claude Code (Anthropic's command-line coding tool) shipped version 2.1.285. Notable additions:

- `claude --desktop` opens the Claude desktop app on your current directory, or on a specific session with `--continue` or `--resume <id>`.
- A new `CLAUDE_CODE_DISABLE_WEB_FETCH` environment variable turns off the WebFetch tool entirely.
- `claude plugin configure <plugin>` shows a plugin's configuration options and which ones aren't set yet, and can save new values piped in from stdin.
- Installing a plugin can now set a bundled MCP (Model Context Protocol — the standard Claude Code uses to connect to external tools) server's own settings at install time, with `<server>.<key>=<value>` added to `claude plugin install --config`. Previously you had to visit the `/plugin` menu's Configure screen afterward to finish setup.
- A new `allowedProviders` managed setting lets an organization admin restrict which API providers a machine may use (for example, only Bedrock or only a specific gateway).
- A new `CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES` environment variable caps how many times a timed-out non-streaming fallback request gets re-sent.

Selected bug fixes:
- Background Bash and PowerShell commands (started with `run_in_background`) now stop automatically after a time limit (30 minutes by default, 2 hours max), and Claude is told when one is stopped.
- A failing API request could previously be retried up to 21 times when streaming kept failing, because the non-streaming fallback got its own fresh set of retries; it now shares the original request's retry budget.
- `claude mcp list` was leaving out MCP servers connected over WebSocket; they're now listed along with their URL and health status.
- Switching models mid-session (for example via the Agent SDK's `setModel`) no longer leaves the new model stuck on the old model's output-token limit and auto-compact window until restart.

## Why it matters

The provider-restriction setting and MCP config-at-install option are aimed at teams managing Claude Code across many machines — they cut down on manual setup steps and give admins tighter control. The retry-budget fix matters for anyone who has seen a single failing request hang for an unusually long time: it should now fail (or succeed) faster instead of quietly retrying up to 21 times. The background-process time limit is a safety net for long-running shell commands that could otherwise run indefinitely unnoticed.

## How to use it

- Update Claude Code to v2.1.285 or later (it self-updates by default, or use your package manager's update command).
- Try `claude --desktop` if you want a one-command way to jump from the terminal into the desktop app on the same project or session.
- Admins: set `allowedProviders` in your managed settings file to lock down which API provider(s) Claude Code can use on a machine.
- If a plugin's bundled MCP server needs configuration, pass its values directly with `claude plugin install --config <server>.<key>=<value>` instead of configuring it afterward.
