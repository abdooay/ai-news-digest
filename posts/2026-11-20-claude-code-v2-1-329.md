## What changed

Claude Code, Anthropic's command-line coding agent, shipped version 2.1.329. As usual, most of the release is small fixes, but a few additions and changes stand out:

- **`/tasks` now shows more.** The command listing background work now includes this session's scheduled tasks, `/loop` wakeups, the session's goal, and any forks (copies of the session doing their own work). Pressing `x` stops one of these, but asks for confirmation first.
- **`/mcp` and `/status` give more diagnostic detail.** A server's page in `/mcp` now shows a "Server message" row with the exact error a remote MCP (Model Context Protocol — the standard Claude Code uses to connect to external tools) server sent back when it refused a connection. `/status` now has a "Marketplace auto-update" row naming any managed plugin marketplaces that don't update automatically, and explaining why.
- **Code Mode works with OpenTelemetry monitoring turned on.** Code Mode lets Claude write and run a script that makes several tool calls at once instead of one at a time. Previously it couldn't run alongside OpenTelemetry (a standard for collecting monitoring data); now each tool call a Code Mode script makes sends its usual telemetry events, though detailed tracing of the script itself still stays off.
- **Several sign-in and stability fixes:** repeated sign-outs on macOS when Claude Code could read credentials from the Keychain but not save to them are fixed — a session now stops cleanly at expiry instead of looping; a config file (`~/.claude.json`) could be wiped back to defaults if a network stall or file lock interrupted a save, which is now fixed; and a runaway loop in Code Mode that could fill a machine's memory is now stopped at a limit.
- **Memory-use improvements:** long sessions that edit many files, Claude Desktop sessions with many large MCP tool results, and idle sessions resumed with saved screenshots or large tool outputs all use less memory than before.
- Many smaller fixes to `/code-review` (it now reads pull requests with `gh pr diff` and says when it can't, instead of silently reviewing the wrong branch), MCP server reconnection, file-type handling for documents sent as generic binary data, and VS Code's permission prompts, trust dialog, and IME (input method editor) text handling.

The release has well over 100 entries in total; the full list is in the changelog linked below.

## Why it matters

The `/tasks` and `/mcp` changes make it easier to see what Claude Code is doing in the background and why an MCP server connection failed, without guessing. That matters more as people run more scheduled tasks, loops, and forked sessions at once — this very digest is one example of a scheduled task that benefits from clearer visibility.

The sign-in and memory fixes are reliability improvements: they stop Claude Code from logging you out repeatedly on macOS, losing your config file during a bad save, or slowly consuming more memory in long-running sessions. None of these require you to change anything — they just make the tool more stable.

## How to use it

- Update with `claude update`, or through your package manager, to get version 2.1.329.
- To check why an MCP server won't connect, open `/mcp` and look at that server's page for the new "Server message" row.
- To see all background work in one place, including scheduled tasks and loop wakeups, run `/tasks`.
- No action is needed for the stability and memory fixes — they apply automatically once you're on this version.
