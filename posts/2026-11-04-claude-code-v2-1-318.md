## What changed

Claude Code is Anthropic's command-line coding agent. Version 2.1.318 is mostly a bug-fix release, with a few small additions:

- **Mod approval is now recorded**: a "mod" is a small change Claude Code writes to its own interface or behavior during a session (for example, adding a shortcut or a panel). Claude Code now keeps a record of your answer when it asks to turn one on.
- **Per-mod effort setting**: a mod's `$.model.fork` config can now set its own `effort` level, so a quick side task can run at `low` effort even if the main session is running at a higher effort. The result reports which effort it actually used.
- **Sign-in expiry is now visible**: `claude auth status` and the JSON output of `claude -p` now show when a stored claude.ai sign-in will expire (`loginExpiresAt` / `credential_expires_at`). A warning also appears in `claude -p` text output starting 10 days before expiry.
- **A new safety check for AWS roles**: `assume_role` can now be set on `mantle` upstreams of the Claude apps gateway (a proxy some companies run in front of Claude), letting a request use a role in another AWS account and get its own per-developer cost tracking.

The rest of the release is fixes. Some of the more user-visible ones:
- `--continue` could lose earlier conversation history after a malformed tool call's retries ran out (a regression from 2.1.314) — fixed.
- macOS sessions running many background shell commands at once could stall as memory grew — fixed.
- Permission prompts could be answered by keystrokes typed just before the prompt appeared, or right after sending a message — fixed.
- On shared network home directories, actions like `/logout`, `claude auth logout`, and `claude mcp remove` could silently fail to save, or report success when they hadn't actually changed anything — fixed, along with several related saving and config-file issues.
- A session could be refused at startup because of an `allowedProviders` list saved by a *different* login on the same machine — fixed.
- Idle compaction (Claude Code automatically shortening a long conversation when idle) could replace the conversation with a reply that wasn't actually a summary — fixed.
- Cloud sessions could be stopped mid-turn if the upload service refused uploads for several minutes — fixed.
- `gh run view --log` and `gh api` log requests in cloud sessions could hit an unreachable redirect instead of returning the log — fixed.

## Why it matters

Most of this release is about Claude Code not losing context, not getting stuck, and not silently failing to save your settings — things that matter most when you're deep in a long session or running on a shared machine. The shared-network-home fixes in particular will matter to anyone running Claude Code on a corporate network drive, where config files could previously be wiped or replaced without warning.

The sign-in expiry visibility is a small but useful change: instead of being logged out with no warning, you now get 10 days' notice before a stored sign-in lapses.

## How to use it

- Update Claude Code with `claude update`, or through your package manager, to get v2.1.318.
- All the bug fixes and the sign-in expiry warning apply automatically — no setup needed.
- To set a lower effort for a mod's forked model call, add `effort` under that mod's `$.model.fork` configuration.
