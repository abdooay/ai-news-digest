## What changed

Claude Code is Anthropic's command-line coding agent. Version 2.1.319 landed on November 6, 2026, with a very long list of changes. The most important ones:

- **Three security fixes**: a sandbox escape that could happen when creating a worktree (a separate working copy of a git branch); a way a crafted environment-variable prefix could hide part of a Bash command from permission checks; and a case where Bash "deny" and "ask" rules could miss commands written with quoted words.
- **Auto mode behind LLM gateways is stricter.** "Auto mode" lets Claude Code approve or block actions on its own using a safety classifier. Before this release, if the classifier's server-side check wasn't reachable — for example behind a company's LLM gateway, or with telemetry or feature flags turned off — Claude Code fell back to a built-in local classifier. Now, in that situation, the action is instead asked about or denied, with no fallback. Setting the environment variable `CLAUDE_CODE_AUTO_MODE_SERVER=0` keeps the old fallback behavior. Amazon Bedrock, Google Vertex, and Microsoft Foundry deployments are unaffected.
- **New `permissions.denyInsteadOfPrompting` setting.** When turned on, a tool call that would normally pause and wait for you to approve or deny it is denied automatically instead, and the session keeps going. This applies in terminal sessions, subagents, and teammates.
- **MCP tool calls now run in the background automatically.** MCP (Model Context Protocol) lets Claude Code connect to external tool servers. When one of those servers runs a tool call as a background "task," Claude Code now moves it to the background right away instead of waiting for it inline, and reports the result to Claude once it finishes. Setting `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1` restores the old wait-inline behavior.
- **New `/claude-api latency-optimize` command**, which looks through your own Claude API code for places that make users wait, and tries faster settings against your evaluation.
- **Self-paced `/loop` now stops itself** when a turn finishes without scheduling another one, instead of always scheduling a fallback wakeup. Setting `CLAUDE_CODE_LOOP_KEEPALIVE=1` restores the old always-reschedule behavior.
- **Removed `shortcuts_list` and `shortcuts_execute`**, the built-in Claude in Chrome tools that listed and ran shortcuts saved in the browser extension.

## Why it matters

The three security fixes are the most important part of this release. A sandbox escape and a permission-check bypass are exactly the kind of bugs that let a crafted command or input run with more access than it's supposed to have — anyone running Claude Code, especially unattended or in shared environments, should update.

The auto mode change mainly affects teams running Claude Code behind an LLM gateway, or with telemetry disabled: actions that used to be quietly approved by a local fallback classifier will now either be asked about or denied outright. That can mean more interruptions in those setups, but it avoids silently approving actions when no real safety check actually ran.

Backgrounding MCP tasks by default should make workflows that rely on slow MCP tools feel faster, since Claude Code no longer sits idle waiting on them.

## How to use it

- Update Claude Code to v2.1.319 or later to pick up the security fixes: run `claude update`, or update through your package manager.
- To keep the old auto-mode fallback behavior behind an LLM gateway, set `CLAUDE_CODE_AUTO_MODE_SERVER=0` in your environment.
- To auto-deny rather than prompt for actions that would otherwise wait on you, add `"permissions": { "denyInsteadOfPrompting": true }` to your settings file.
- To keep MCP tool calls blocking instead of running in the background, set `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1`.
- Try the new latency tool with `/claude-api latency-optimize`.
