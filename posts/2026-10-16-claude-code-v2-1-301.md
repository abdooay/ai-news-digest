## What changed

Claude Code is Anthropic's command-line coding agent. It shipped v2.1.301 with these changes:

- **Unattended retry mode** (`CLAUDE_CODE_RETRY_WATCHDOG`) automatically retries a request that hit a usage limit. A new environment variable, `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS`, lets it give up and end the request instead of waiting, if the usage limit won't reset for longer than that.
- **Vim mode** gained the `%` motion: jump to a matching bracket, on its own or combined with delete/change/yank (`d%`, `c%`, `y%`).
- Plugin authors ("mods") can now use `rows` on a text `Input` field to get a multi-line box in the terminal, where Enter submits and Shift+Enter (or a trailing backslash) adds a new line.
- OpenTelemetry tracing (sending usage data to an external monitoring tool) now includes `classifier_verdict` and `permission_mode` on tool-decision events, so you can tell apart a decision made by the auto-mode classifier from one made by a plain permission rule, plus `classifier_category` naming which built-in rule blocked a tool call.
- Dozens of bug fixes, including: quitting no longer silently removes a worktree (an extra working copy of your repo) that might hold unpushed commits; the `fable`/`best` model alias no longer errors when the newest Fable model isn't available to your organization (it retries on the previous one); Grep and Glob now report a real error instead of "no matches" when the search itself fails; and several terminal-rendering and vim-mode glitches are fixed.
- VS Code extension: added LaTeX math rendering (`$$`, `\[ \]`, inline `$...$` and `\(...\)`) in Claude's responses, and a "Get more usage" link on the usage-limit banner for Pro and Max plans.

## Why it matters

Most of this release is maintenance: bug fixes for worktrees, vim mode, terminal rendering, and sign-in reliability that affect day-to-day use without changing how you work. The one feature with broader relevance is the new retry-watchdog cutoff — if you run Claude Code unattended (e.g. in CI or a scheduled job) and rely on automatic retries after hitting a usage limit, you can now cap how long it will wait before giving up, instead of it waiting indefinitely for a limit that resets far in the future.

## How to use it

- Update with `claude update`, or through your package manager.
- To cap unattended retry waiting, set `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS` (in milliseconds) alongside `CLAUDE_CODE_RETRY_WATCHDOG`.
- Try the new vim bracket motion with `%`, `d%`, `c%`, or `y%` in vim mode.
- VS Code users get LaTeX rendering and the usage-limit link automatically after updating.
