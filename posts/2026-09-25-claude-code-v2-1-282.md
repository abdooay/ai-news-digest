## What changed

Claude Code (Anthropic's command-line coding agent) shipped v2.1.282, another release made mostly of bug fixes. The notable additions:

- **`maxProseWidth` setting**: caps how wide Claude's prose text can stretch in a wide terminal window, while tables and code blocks still use the full width.
- **Telemetry notices**: a new startup notice, plus entries in `/status` and `claude doctor` (Claude Code's built-in diagnostics command), list any telemetry environment variables in a project's settings files that were ignored or that turned telemetry off.
- **`allowClaudeInChromeWithManagedMcp`**: a new managed setting (one an organization admin sets, not an individual user) that lets `claude --chrome` (Claude Code's browser-control mode) run even when an organization has locked down MCP servers with an exclusive `managed-mcp.json` config file. The error message shown when Chrome is blocked now names the setting that's blocking it.

On the fix side, several bugs involved Claude silently losing its "extended thinking" (the reasoning Claude does before answering, when that feature is turned on):
- Thinking could be dropped when you used `/model`, `/rename`, `/artifacts`, or another slash command while Claude was still working on a response.
- Thinking could be lost when resuming a conversation with `--continue` or `--resume` using a `--tools` list that leaves out a built-in tool the earlier conversation had access to.
- Sessions could fail on every turn with an "Invalid `data` in `redacted_thinking` block" API error; Claude Code now drops the broken thinking data and retries once automatically.

Other fixes: requests failing with a 400 error when conversation history contains web search results the API can't decrypt (for example, from a turn originally answered through a third-party gateway); resumed sessions re-sending earlier messages in a changed form; and compaction (Claude Code's automatic conversation-summarizing step) failing outright when the summarization request gets refused, which now retries on a fallback model instead.

## Why it matters

The extended-thinking fixes matter for anyone who relies on Claude's reasoning quality in long or resumed sessions — losing that reasoning mid-task could make follow-up answers worse without any visible error. The compaction and 400-error fixes reduce cases where a long-running session would simply stop working. `maxProseWidth` is a smaller quality-of-life fix for people running Claude Code in very wide terminal windows or tiled layouts, where long lines of prose can become hard to read.

## How to use it

- Update with `claude update`, or through whichever package manager you installed Claude Code with, to reach v2.1.282.
- To try the new setting, add `"maxProseWidth"` to your Claude Code settings file (the exact key format follows Claude Code's usual settings schema).
- The thinking and session fixes apply automatically once you update; no configuration is needed.
- Organization admins using an exclusive `managed-mcp.json` can set `allowClaudeInChromeWithManagedMcp` to let `claude --chrome` keep working for their users.
