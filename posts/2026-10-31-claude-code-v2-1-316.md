## What changed

Claude Code is Anthropic's command-line coding agent. Version 2.1.316 adds several settings and confirms a model change that also applies to the Claude API directly:

- **Turn off `ultrathink`**: a new environment variable, `CLAUDE_CODE_DISABLE_ULTRATHINK`, disables the `ultrathink` keyword (a prompt trigger that tells Claude to reason longer before answering).
- **Default subagent effort**: `CLAUDE_CODE_SUBAGENT_EFFORT` sets the effort level (how much the model reasons before responding) that subagents use when nothing else specifies one, instead of automatically inheriting the main session's effort level.
- **Gateway changes for organizations**: admins running the Claude apps gateway (a proxy some companies put in front of Claude) can now set `pooled_budget` so a group of developers shares one monthly spending budget on top of each person's own limit, and can set `managed.policy_mode: layered` so that every policy matching a developer applies together, each layered over the ones below it, instead of only the first match winning. Gateway admins on Amazon Bedrock can also turn on `guardrail.input_tagging`, which wraps prompts in the tags Bedrock's "prompt attacks" guardrail filter expects.
- **Fast mode retires for Claude Opus 4.8**: as of October 30, 2026, fast mode (a faster-response mode for Opus 4.8) is deprecated and will be removed on November 30, 2026. After that date, a fast-mode request to Opus 4.8 returns an error instead of silently falling back to standard Opus 4.8. This same change was announced separately in the Claude API's own release notes, where it applies to any API request that sets `claude-opus-4-8` with `speed: "fast"` — the deprecation isn't specific to Claude Code. Anthropic says to migrate to Claude Opus 5.5 to keep the speed.

The release also fixes a long list of smaller bugs: shell commands left running after Claude Code exits, bash aliases and dash-prefixed function names getting mangled, a PowerShell hook that failed to block on certain commands, Vertex AI/Amazon Bedrock sessions showing a hard error instead of falling back to an older model when the newest one isn't available yet, and gateway requests that named a blocked model slipping through some checks (they now get a clear 400 error).

## Why it matters

The `ultrathink` and subagent effort settings give teams more control over cost and latency: `ultrathink` triggers long, expensive reasoning, so being able to disable it organization-wide prevents surprise costs, and setting a default subagent effort avoids subagents silently running at the same (possibly expensive) effort as the main session. The gateway features mainly matter to organizations with many developers sharing one Claude deployment — pooled budgets make team-wide spending limits easier to manage, and layered policies let admins combine rules instead of relying on whichever one happens to match first.

The fast mode retirement affects anyone using Opus 4.8's fast mode today, whether through Claude Code, the Claude API, or another Anthropic surface: after November 30, 2026, those requests will fail instead of quietly running at normal speed, so this needs to be fixed before the deadline rather than after.

## How to use it

- Update Claude Code with `claude update`, or through your package manager, to get v2.1.316.
- To turn off `ultrathink`, set the environment variable `CLAUDE_CODE_DISABLE_ULTRATHINK=1`.
- To set a default subagent effort level, set `CLAUDE_CODE_SUBAGENT_EFFORT` to the desired level (e.g. `low`, `medium`, `high`).
- Pooled budgets, layered policy mode, and Bedrock input tagging are configured by whoever manages your organization's Claude apps gateway, using `pooled_budget`, `managed.policy_mode: layered`, and `guardrail.input_tagging` respectively.
- If you or your organization use fast mode with Claude Opus 4.8 — in Claude Code, the Claude API, or elsewhere — plan to migrate to Claude Opus 5.5 before November 30, 2026, after which fast-mode requests to Opus 4.8 will simply error out.
