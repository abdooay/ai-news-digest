## What changed

Claude Code is Anthropic's command-line coding agent. Version 2.1.314 is mostly a security and reliability release. The main additions:

- **Write protection**: a new setting, `permissions.blockWritesOutsideWorkingDirectories`, makes the `Write`, `Edit`, and `NotebookEdit` tools refuse to touch any file path outside your project's working directories — in every permission mode, including the more permissive ones.
- **Gateway access control**: organizations running the Claude apps gateway (a proxy some companies put in front of Claude) can now limit an upstream connection to only developers in specific identity-provider (IdP) groups, and this restriction still applies if the gateway fails over to a backup upstream.
- **Bedrock guardrail logging**: gateway admins using Amazon Bedrock can now log which Bedrock guardrail filter blocked a request (`guardrail_trace`), without logging the actual text that triggered it.
- **Idle compaction**: in VS Code and Claude Desktop's Code tab, a conversation that passes 200,000 tokens and then sits idle is automatically summarized in the background, so the summary is ready the next time you send a message.

Notable fixes:
- Sessions no longer get stuck failing every turn with "Invalid effort level" when an organization's admin caps how much effort a model can use — Claude Code now automatically lowers the effort and retries.
- `claude -p` (the non-interactive/scripting mode) used to exit with code 0 and no output at all if startup failed; it now prints the error and exits with code 1.
- Fixed TLS connection failures (`UNABLE_TO_GET_ISSUER_CERT`) that happened when a computer's certificate store held a renewed root certificate cross-signed with its predecessor.
- Fixed MCP servers (Model Context Protocol tool integrations) that work without sign-in incorrectly showing "needs authentication" after a stored sign-in stopped working.
- Fixed a bug where one broken plugin manifest could block switching models entirely on machines using managed plugin settings.
- Many smaller fixes to the transcript view, vim mode, the agent panel, cloud sessions, Remote Control, and Claude Tag (Claude in Slack).

## Why it matters

The write-protection setting is the headline change: without it, Claude's file-editing tools could be told (accidentally, or by a prompt injection in something Claude read) to write a file somewhere outside the project, such as a shared config file elsewhere on disk. Organizations that need this guarantee can now turn it on and have it hold in every permission mode, not just the strictest one. The `claude -p` fix matters for anyone who scripts or automates Claude Code — a silent, zero-output failure is much harder to debug than a visible error with a non-zero exit code. The idle compaction feature mainly helps people with long-running VS Code or Desktop sessions avoid a slow "summarizing now" wait right when they come back to a conversation.

## How to use it

- Update with `claude update`, or through your package manager, to get this release.
- To turn on write protection, set `permissions.blockWritesOutsideWorkingDirectories: true` in your Claude Code settings.
- The gateway IdP-group restriction and Bedrock guardrail trace logging are configured by whoever manages your organization's Claude apps gateway.
- Idle compaction in VS Code/Desktop and the other bug fixes apply automatically — no setup needed.
