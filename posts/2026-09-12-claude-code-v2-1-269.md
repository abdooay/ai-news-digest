## What changed

Claude Code, Anthropic's command-line coding agent, shipped v2.1.269. Highlights from this release:

- New `claude plugin eval` command: runs a plugin's eval suite (a set of test tasks used to score how well a plugin performs) against Claude Code and produces a scored, reproducible report in JSON and HTML. See `claude plugin eval --help` for options.
- New `/output-style [name]` command lists and switches output styles (preset instructions that change how Claude formats its replies), including when using Remote Control or in cloud and other headless sessions.
- When the Bash tool is used to edit files directly, its result can now include a diff of what changed, controlled by a new `bashEditDiffEnabled` setting.
- New environment variables for advanced setups: `OTEL_METRICS_INCLUDE_REPOSITORY` tags OpenTelemetry (a standard for collecting metrics and logs) data with repository info, and `CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS` extends how long Claude Code waits when discovering models through an organization's self-hosted gateway.
- New `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` (1-256) setting raises the limit on how many agents a Workflow run can run at once, for workflows that spend most of their time waiting on model responses rather than CPU.
- A large batch of bug fixes, including: several terminal key-handling regressions (F1/F2/F4 in kitty-protocol terminals, Delete in `st`, Alt+arrows in `rxvt-unicode`, Shift+punctuation in WezTerm); a prompt-cache invalidation bug after a cut-off response was auto-resumed; permission rules with a leading `!` leaking beyond the settings file that defined them; and remote/headless sessions incorrectly showing "waiting for your input" while background agents were still running.

## Why it matters

The `claude plugin eval` command gives plugin authors a repeatable way to measure whether a change to their plugin helped or hurt, instead of relying on manual spot checks. The output-style switching command and the Bash diff feature are both about visibility: knowing what mode Claude is replying in, and seeing exactly what a Bash-driven edit touched, without having to dig through the transcript. The fixes matter most to people who hit the specific bugs — several terminal-specific keyboard issues, a permission-rule scoping bug, and a status-reporting bug in headless and remote sessions that could be confusing when checking whether a session actually needed attention.

## How to use it

- Update with `claude update`, or through your package manager.
- Run `claude plugin eval --help` to see how to run a plugin's eval suite.
- Run `/output-style` to see available output styles, or `/output-style <name>` to switch.
- Set `bashEditDiffEnabled` to turn on diffs for Bash-driven file edits.
- Everything else applies automatically after updating.
