## What changed

Claude Code, Anthropic's command-line coding agent, shipped v2.1.273. It's a large release with dozens of fixes and small improvements. The notable ones:

- **Fixed a sandbox bypass**: in "bypass mode" (where Claude Code skips permission prompts), a command could hide a dangerous `rm` (delete) call inside a subshell and it would run without being caught. That gap is now closed. A related fix: Bash commands the permission checker can't fully analyze no longer skip the prompt required by `permissions.blockReadsOutsideWorkingDirectories`, a setting that stops Claude Code from reading files outside your project folder.
- **Fixed the context meter over-counting**: the context meter (the indicator showing how much of the model's context window is used) and auto-compact (which automatically summarizes old conversation to free up space) were counting "advisor" tool turns at roughly twice their real size. That made auto-compact trigger at about half the context window it was supposed to use, cutting sessions short and summarizing more often than necessary.
- **Session forking for Remote Control**: a session started with `claude --remote-control` or the `/remote-control` command from the Claude app can now be "forked" — split into a new session that keeps running as a background session on your own computer, separate from the original.
- **New LLM gateway headers**: for teams routing Claude Code traffic through their own LLM gateway, new opt-in request headers (`x-claude-code-request-class`, `x-claude-code-agent-type`, `x-claude-code-prev-tool-durations`, `x-claude-code-compaction`, `x-claude-code-context-compacted`) expose more detail about each request. Enable them with the environment variable `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`.
- **MCP disconnect notifications**: if an MCP server (a Model Context Protocol server — a plugin that gives Claude Code access to external tools or data) disconnects mid-session and automatic reconnection fails, Claude Code now tells you and points to the `/mcp` command to fix it.
- **Skills removed by an organization are now recoverable**: if your organization turns off Skills (packaged instruction sets) after you've synced some from claude.ai, they used to stay silently available. They now move to a recoverable trash instead of lingering active.
- **Clearer credential errors**: 401/403 authorization errors on Bedrock, Vertex, Foundry, or the Claude apps gateway now name the specific credential to refresh, or point you to your gateway administrator, instead of a generic error.
- A long list of smaller fixes: login/upgrade commands no longer discard earlier thinking and force a full prompt-cache rewrite; a dragged-in screenshot on macOS is no longer refused with a symlink error; saved scheduled tasks no longer run in the wrong session after being copied into a new folder or worktree; sub-agents are no longer reported as failed when their final reply is missing token-usage data; and several editor- and platform-specific fixes for VS Code, Claude Code on the web, and Claude Tag (Claude in Slack).

## Why it matters

The sandbox bypass fix and the `blockReadsOutsideWorkingDirectories` fix are both security-relevant: they close gaps where a command could do more than the sandbox or permission settings were meant to allow. The auto-compact fix matters for anyone doing long sessions with advisor tools — compaction was firing roughly twice as often as intended, which meant losing conversation history sooner than necessary. Session forking gives people using Remote Control (running Claude Code on a phone or another device against a session on their computer) more flexibility to split work off without disrupting the original session.

## How to use it

- Update with `claude update`, or through your package manager, to get the fixes automatically — most require no configuration.
- To see the new gateway request headers, set `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` in your environment.
- To fork a Remote Control session, use the fork option from a session started with `claude --remote-control` or `/remote-control`.
- If an MCP server disconnects and won't reconnect, run `/mcp` to check its status.
