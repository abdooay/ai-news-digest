## What changed

Claude Code (Anthropic's command-line coding agent) released version 2.1.259. Main changes:

- **Managed MCP servers.** A new `managedMcpServers` setting lets an organization provide HTTP/SSE MCP servers (external tool connections) to every user automatically, using the same format as a project's `.mcp.json` file. Entries that try to run a local command are skipped for safety — only remote HTTP/SSE servers can be pushed this way.
- **`--permission-prompts none`.** A new flag for unattended, headless machines. Anything that would normally pop up a permission prompt is denied automatically instead of hanging, while whatever permission mode is active (including auto mode) still makes its normal decisions.
- **GitLab merge request recognition.** Claude Code now recognizes `glab mr create/merge/close/reopen/note/update` commands, showing them as `MR !N` in the tool-call summary and updating a merge-request status badge in the footer.
- **`claude plugin validate --json`** adds a machine-readable output format for plugin validation, useful for CI pipelines.
- **`allowedMcpServers` behavior change.** This setting now only governs MCP servers that users add themselves. A server named literally `managed-mcp.json` that an allowlist used to filter out will now load automatically after upgrading; use the separate `deniedMcpServers` setting if you need to block it.

Notable fixes in this release:
- Fixed concurrent Claude Code sessions silently overwriting each other's `~/.claude.json` settings file, which could reset workspace trust or lose MCP/project state when running multiple sessions at once.
- Fixed a bug where, once a session's "thinking" content was rejected once, it kept getting rejected on every later turn.
- Fixed several gaps in Bash "deny" rules (rules that block specific commands) — they now also catch files passed as option values (like `--ignore-revs-file=.env`), `git diff`/`git grep` file arguments, and `cd DIR && cat FILE` command chains.
- Fixed fullscreen mode showing a blank conversation after a long turn with hundreds of tool calls.
- Fixed prompt cache invalidation when an OAuth token refreshed in sessions with telemetry disabled.
- Fixed `CLAUDE_CODE_MAX_CONTEXT_TOKENS` being ignored for certain Vertex AI model IDs.

## Why it matters

The managed MCP server feature matters most for companies: an admin can now roll out approved tool connections to every developer's Claude Code without each person configuring it individually. The `--permission-prompts none` flag is aimed at CI/automation setups where no one is present to click "allow" — instead of a session hanging forever waiting for input, it now fails safe by denying. The `~/.claude.json` fix is important for anyone who regularly runs several Claude Code sessions at once, since the bug could silently lose settings or project trust.

## How to use it

- Update with `claude update`, or through your package manager.
- To push MCP servers to your whole organization, set `managedMcpServers` in your managed settings file (the same shape as `.mcp.json` entries, HTTP/SSE only).
- For unattended or CI machines, pass `--permission-prompts none` on the command line.
- No action is needed for the bug fixes — they apply automatically after updating.
