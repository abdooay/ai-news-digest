## What changed

Claude Code, Anthropic's command-line coding agent, shipped v2.1.274. Highlights:

- **Low-memory warning**: if Claude Code detects the machine is critically low on memory, it now shows a warning with steps to free memory or restart safely, instead of just slowing down or crashing.
- **MCP (Model Context Protocol) fixes**: MCP is the standard Claude Code uses to connect to external tools and data sources. This release fixes several MCP bugs: servers configured as `http` no longer fail to connect on 422 or other 4xx errors; Streamable HTTP MCP tool calls no longer time out after around 5 minutes; and MCP prompts and resources now refresh properly when the server sends a list-changed notification. A new `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` setting also controls how long the first non-interactive turn waits for MCP servers to finish connecting.
- **Session recovery**: sessions that got stuck retrying "unexpected tool_use_id" errors are now automatically self-healed by repairing the transcript, instead of getting stuck in a retry loop.
- **`/goal` no longer lost after compaction**: resuming a session that had gone through compaction (automatic summarizing of old conversation to save space) used to sometimes drop the tracked `/goal`. That's fixed.
- **Telemetry additions**: an `effort` attribute was added to the `claude_code.llm_request` OpenTelemetry trace span, and a new `claude_code.managed_settings_resolved` event reports where an organization's managed settings came from.
- Smaller fixes: `claude agents` no longer loses its command-line flags after auto-updating and relaunching; transcripts no longer renumber ordered lists inside user messages incorrectly; plugin and marketplace clones now use Git LFS pointers instead of downloading full files; and various VS Code, Claude Code on the web, and Claude Tag (Claude in Slack) improvements.

## Why it matters

The MCP fixes matter most for anyone relying on external tool servers: a connection that silently times out or never refreshes its tool list can make Claude Code miss capabilities without an obvious error. Automatic transcript self-healing means a specific class of stuck sessions now recovers on its own instead of requiring the user to start over. The low-memory warning helps catch a failure mode — running out of memory mid-session — before it causes confusing errors.

## How to use it

- Update with `claude update`, or through your package manager. Most of these fixes apply automatically.
- If you use MCP servers over HTTP and hit connection issues, this release is worth updating to directly.
- To tune how long Claude Code waits for MCP servers on startup, set `CLAUDE_CODE_MCP_STARTUP_WAIT_MS`.
