## What changed

Claude Code, Anthropic's command-line coding agent, shipped v2.1.332. Highlights:

- **Skills from MCP servers (beta)**: a skill, a packaged set of instructions for a task, can now come from an MCP server (a plugin-like server that extends Claude's tools). These show up in the `/` menu as `server:skill`.
- **New hook: `PreSkillShellCommand`**: this hook event can block a skill's or slash command's inline shell commands while it is loading, before they run.
- **Message handling**: an "always deliver" option for held messages from other sessions, and a footer note when a flagged message's session is running on a different model than expected.
- **Status visibility**: VS Code and the Desktop app's Code tab now warn about unsaved session data and about resumed sessions where some earlier messages didn't load. The startup header can show your Cyber Verification Program access tier (a security-vetting level for some enterprise accounts).
- **Reliability fixes**: `claude auth login` now exits with an error instead of wrongly reporting success when it can't save the login. Several hangs and freezes are fixed, including issues with named pipes, permission rules with many wildcards, hooks or MCP servers that produce endless output, very long `@`-mention strings, and repeated failed auto-compaction (the process that shortens a long conversation to fit it back in context).
- **Cloud provider fixes**: many fixes to model selection and fallback on Amazon Bedrock, Google Cloud's Agent Platform, and Microsoft Foundry, including alias handling (e.g. what `sonnet` or `opus` points to) and the `availableModels` setting. The default Foundry model is now Sonnet 5.5, and Foundry now treats Sonnet 4, Opus 4, and Opus 4.1 as retired.
- **Changed defaults**: Sonnet 5 and 5.5 sessions on several cloud platforms now default to "auto mode" (the agent runs without stopping for routine confirmations) unless `disableAutoMode` is set.
- Smaller fixes to Grep, notebook cell editing, Code Mode (Claude writing and running short scripts instead of calling tools one at a time), Windows file search speed, and terminal keybindings.

## Why it matters

The MCP skills beta means teams can ship a skill alongside an MCP server instead of as a separate plugin, so a single server install can add both tools and the instructions for using them. The `PreSkillShellCommand` hook gives security-conscious teams a way to review or block shell commands a skill tries to run automatically, which matters if you load skills from sources you don't fully control. The reliability and cloud-provider fixes don't add features, but they close off specific hangs and misconfigurations that affected real users, especially those running Claude Code through Bedrock, Google Cloud, or Foundry rather than the Claude API directly.

## How to use it

- Update with `claude update`, or through your package manager, to reach v2.1.332.
- To try an MCP-server skill, install an MCP server that ships one; it will appear in the `/` menu as `server:skill`.
- To block a skill's shell commands, add a `PreSkillShellCommand` hook in your settings.
- If you're on a cloud platform (Bedrock, Google Cloud, Foundry) and don't want auto mode on by default for Sonnet 5/5.5 sessions, set `disableAutoMode`.
