## What changed

Claude Code, Anthropic's command-line coding agent, shipped version 2.1.325. Like recent releases, it's mostly a long list of fixes, but a few changes matter for anyone running it day to day:

- **Security fix:** a bug in how Claude Code decodes zstd-compressed network responses has been fixed. The changelog doesn't give more detail on what the bug allowed.
- **Sandboxed terminal commands now ask by default.** Claude Code can run shell commands inside a sandbox (an isolated environment that limits what a command can touch). Previously, sandboxed commands ran without asking for permission. Now they follow the normal "ask before running" flow unless you set `sandbox.autoAllowBashIfSandboxed: true`.
- **Stricter permission checks for shell commands:** some compound commands (commands chained together, e.g. with `&&` or `;`) that previously ran without asking will now ask for permission. A rule that allows one program to run can no longer be used to sneak a different program through.
- **Read-only git commands now ask first** in a folder that isn't the project you started Claude Code in, or one you've already told it to trust. Add the folder with `--add-dir` to avoid being asked each time.
- **Scheduled tasks and `/loop` now ask before running a skill** that declares its own tool permissions (`allowed-tools`) or hooks, instead of running it unattended. To keep a scheduled skill running without prompts, add `Skill(name)` to your permission allow-list.
- Smaller fixes: subagents on a different model no longer get silently switched to the plan-mode model; sessions on some third-party model gateways no longer hit a context-length error every turn; a saved `sonnet[1m]` model setting is no longer corrupted on a fresh install.
- VS Code: added inline prompt suggestions you can accept with Tab, a sign-in option that doesn't create an API key, and a field for pasting a redirect URL when signing in to an MCP (Model Context Protocol) server from a remote window.
- Claude Code on the web (cloud sessions): the limit on how long an MCP tool's description can be before it gets cut off was raised from 4,096 to 16,384 characters, matching other versions of Claude Code.

The release has well over 100 other small fixes across sign-in, MCP servers, plugins, and Windows/Linux — too many to list here; see the full changelog linked below.

## Why it matters

The permission changes are the part worth noticing. If you run Claude Code with the sandbox turned on, or use scheduled tasks or `/loop` with skills that have their own permissions, this update can make Claude Code ask you for approval in places it didn't before. That's a deliberate tightening, not a bug — it closes gaps where commands could run, or skills could execute, without a human in the loop. If you rely on unattended runs (for example, this very digest runs on a schedule), check that your permission allow-list still covers what you need after updating, or runs may start pausing for approval where they used to proceed automatically.

The zstd decoding fix is a security patch; Anthropic didn't publish exploit details, which is normal practice until users have had time to update.

## How to use it

- Update with `claude update`, or through your package manager, to get version 2.1.325.
- If you use the sandbox and want commands to keep running without prompts, add `"sandbox": {"autoAllowBashIfSandboxed": true}` to your settings.
- If a scheduled task or `/loop` run uses a skill with its own tool permissions or hooks, add `Skill(<name>)` to `permissions.allow` so it keeps running unattended.
- No action is needed for the other fixes — they apply automatically once you're on this version.
