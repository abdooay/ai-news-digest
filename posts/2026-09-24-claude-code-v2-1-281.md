## What changed

Claude Code (Anthropic's command-line coding agent) shipped v2.1.281, a large release mostly made up of bug fixes. A few changes stand out:

- **Security fix**: Claude Code normally asks for permission before running a recursive delete command (`rm -rf`) that looks dangerous. It turned out a command like `rm -rf "$(pwd)"` — where the target is produced by another command instead of written out directly — could slip past that check and run without asking, even in auto mode or with `--dangerously-skip-permissions` (modes that reduce or skip permission prompts). This is now fixed: Claude Code asks for confirmation even if a Bash allow-list rule would normally let it run automatically.
- **Session resuming**: several fixes address sessions losing context or breaking their prompt cache (saved, reusable parts of a conversation that make follow-up requests faster and cheaper) when resumed after a crash, restart, or a dropped connection to a proxy or gateway (a server that sits between Claude Code and Anthropic's API).
- **Claude apps gateway**: added support for newer Claude Desktop sign-in keys, an `assume_role` option so a gateway can call Amazon Bedrock as a different IAM role, and the ability to attach an Amazon Bedrock "guardrail" (a set of content and behavior rules) to every request sent through it.
- **Claude Code on the web**: added a "Fast mode" switch to the model menu in cloud sessions, for plans that include it.
- **Claude Tag (Claude in Slack)**: fixed several bugs where Claude could stop responding in a Slack thread — after someone pressed Stop, after very long threads, or after a crash mid-task — and would either not recover or recover with a delay of many minutes.
- **`/insights`**: now estimates how many permission prompts auto mode (Claude Code's automatic effort-level and permission decision-maker) could have handled for you, based on your recent sessions.
- Many smaller fixes to keyboard shortcuts, dialogs, vim-mode text editing, and the `/plugin`, `/skills`, and `/workflows` screens.

## Why it matters

The `rm -rf` fix matters most for anyone running Claude Code with reduced supervision — auto mode or `--dangerously-skip-permissions` — since it closes a specific way a destructive delete command could have run without a confirmation prompt. The session-resume fixes reduce a common source of frustration: a resumed session silently losing earlier context or needing to reprocess (and repay for) work it had already cached.

## How to use it

- Update with `claude update`, or through the package manager you installed Claude Code with, to reach v2.1.281.
- The `rm -rf` fix applies automatically; if you relied on the old (unsafe) behavior for a specific automated workflow, you can restore it by setting `CLAUDE_CODE_DISABLE_SUBSTITUTION_RM_PROMPT=1`, but this brings back the risk the fix addresses.
- Cloud session users can find the new Fast mode switch in the model menu of the composer, if their plan includes it.
