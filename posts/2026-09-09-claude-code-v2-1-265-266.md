## What changed

Claude Code (Anthropic's command-line coding agent) shipped two versions on September 8, 2026.

**v2.1.265** added a few new features:
- Two new telemetry fields, `user.email` and `user.groups`, are now sent for sessions that go through an LLM gateway (a proxy server that sits between Claude Code and Anthropic's API, often used by companies to manage API keys and logging).
- The `--plugin-dir` flag now accepts a folder containing multiple plugins, not just a single plugin, and loads them dynamically.
- Tool results saved to disk are now capped at 1 GB total, so a single large result can't fill up your disk.

It also fixed a long list of bugs: resuming subagents after the terminal window closes or a process dies mid-tool-call, prompt-cache reuse for resumed subagents, a rejected `/model opusplan` command, syntax highlighting glitches in permission prompts, a security check on plugin folders that used symlinks (a plugin could bypass a path check meant to keep it contained to its own folder), several Remote Control (controlling a Claude Code session from another device) issues, and many smaller UI and reliability fixes.

**v2.1.266** followed the same day to fix a regression that v2.1.265 itself introduced. Some setups that use an LLM gateway or proxy rely on an undocumented environment variable, `CLAUDE_CODE_USE_GATEWAY`. Before v2.1.265, Claude Code only acted on this variable if two other settings (`ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`) were also set. In v2.1.265, the variable started forcing a sign-in to Anthropic's own Cloud gateway on its own, which broke every request for anyone who had it set alongside a different auth method, such as an API key or a custom auth header. Every such request failed with the error "Not signed in to the Cloud gateway." v2.1.266 restores the old behavior: the variable is ignored again unless it's paired with the other settings.

## Why it matters

Most of v2.1.265's changes are incremental fixes rather than new capabilities you need to seek out, but the 1 GB disk cap on tool results is a good safety net if you run commands that can produce huge output. If your organization runs Claude Code through a gateway or proxy and you upgraded to v2.1.265, you may have hit the sign-in failure — v2.1.266 fixes it, so there's nothing left to work around if you're on the latest version.

## How to use it

- Update with `claude update`, or through your package manager.
- If you were affected by the v2.1.265 gateway sign-in failure, updating to v2.1.266 (or later) resolves it with no configuration changes needed.
- Try `--plugin-dir <folder>` if you maintain several local plugins and want to load them all at once instead of one at a time.
